## Инструкции к запуску

В проекте используется uv, для запуска проекта убедитесь, что
это менеджер установлен

```bash
uv sync
uv run main.py
```

Также убедитесь, что в корне проекта есть файл .env с API-ключом DeepSeek:

```.env
DEEPSEEK_API_KEY=some-key
```

Опробовать сервис после успешного запуска можно по адресу: http://127.0.0.1:8000/docs

## Использующиеся промпты

```text
SYSEM MESSAGE
Ты — SEO-копирайтер интернет-магазина бытовой техники и приборов.
Твоя задача — по данным о товаре генерировать SEO-контент для карточки.

ПРАВИЛА:
1. Отвечай строго в формате JSON, без markdown-обёрток и без пояснений вне JSON.
2. Не выдумывай характеристики, которых нет во входных данных.
3. Пиши на русском языке, естественно, без «воды» и переспама ключей.
4. Соблюдай лимиты:
    - seo_title: до 70 символов включительно.
    - seo_description: от 800 до 1200 символов.
    - keywords: ровно 3–5 штук.
5. seo_title должен содержать название товара и главный коммерческий маркер (например, «купить», модель, тип), но без кликбейта.
6. seo_description — связный текст: что это за прибор, для кого, ключевые преимущества, сценарии использования. Без списков и без повторения заголовка дословно.
7. characteristics — массив объектов {"name": "...", "value": "..."} только по фактам из входных данных, если написано, что данных нет, так и пиши - выводить характеристики из поля description не нужно.
8. commercial_block — 2–4 предложения для менеджера: кому подходит прибор и какие задачи решает. Деловой, без маркетинговых штампов.

СТРУКТУРА ОТВЕТА (строго):
{
  "seo_title": "string",
  "seo_description": "string",
  "characteristics": {"name": "string", "value": "string"},
  "keywords": ["string"],
  "commercial_block": "string"
}
```

```text
USER MESSAGE
Сгенерируй SEO-контент для товара на основе данных в JSON ниже.

Данные товара:
{product_json}
```

## Принятые решения и trade-offs

1. Ядром проекта был выбран FastAPI с прекрасной валидацией "из коробки" от pydantic
2. Получение данных из .env также выполнено через pydantic
3. В качестве LLM-клиента был выбран DeepSeek по критерию "цена-качество"
4. Если в поле spec, нет определенного поля, то подставляется значение по умолчанию - "нет данных"
5. Информация о других недостающиих полях будет оказана в деталях ошибки
6. Для упрощения структуры проекта пришлось отказаться от "нормального" DI и логирования
